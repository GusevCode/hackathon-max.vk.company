# Проверка MVP «ЖКХ Контроль»

Документ описывает проверку этапов 1–4 после деплоя. Пользовательские действия
выполняются через кнопки MAX и пошаговые подсказки. Команды вручную вводить не
нужно.

## 1. Переменные на VPS

В `.env` должны быть заполнены:

```dotenv
APP_NAME=ЖКХ Контроль
MAX_BOT_TOKEN=...
INITIAL_ADMIN_MAX_USER_ID=<MAX ID администратора>
PUBLIC_BASE_URL=https://max.conspiracy-team.ru
MAX_WEBHOOK_SECRET=<не короче 5 символов>
TARANTOOL_PASSWORD=<пароль>
OBJECT_STORAGE_ACCESS_KEY=admin
OBJECT_STORAGE_SECRET_KEY=<длинный пароль>
OBJECT_STORAGE_ENDPOINT=seaweedfs:8333
OBJECT_STORAGE_BUCKET=work-evidence
```

Запуск выполняется production-профилем:

```bash
docker compose --profile https up -d --build
docker compose logs -f bot
```

В логе должны появиться `MAX bot connected`, `Tarantool connected`,
`object storage connected` и `control bot started`.

## 2. Сценарий ролей через меню

### Подключение пользователей

1. Администратор открывает бота — появляется «🛡 Администрирование».
2. Открывает «🎟 Пригласить пользователя».
3. Выбирает роль: «🏢 Управляющий», «🧑‍💼 Руководитель» или «👷 Сотрудник».
4. Передаёт полученный код пользователю.
5. Новый пользователь открывает бота, нажимает «🎟 Ввести код приглашения» и
   отправляет код обычным сообщением.
6. После регистрации пользователь видит только доступные ему разделы.

Управляющий может приглашать руководителей и сотрудников. Администратор может
создавать приглашения для всех трёх ролей, включая управляющего.

### Назначение руководителя

1. Управляющий или администратор открывает «👥 Команда».
2. Выбирает сотрудника.
3. Нажимает «🧑‍💼 Назначить руководителя».
4. Выбирает руководителя из списка.

### Создание задания

1. Руководитель, управляющий или администратор нажимает «➕ Новое задание».
2. Вводит название и описание по подсказкам бота.
3. Выбирает сотрудника кнопкой.
4. Вводит срок в формате `ДД.ММ.ГГГГ`.
5. Выбирает объект и вид работы либо пропускает эти шаги.
6. Подтверждает карточку кнопкой «✅ Создать».

### Исполнение и проверка

1. Сотрудник открывает «📋 Мои задания» и выбирает карточку.
2. Нажимает «▶️ Взять в работу».
3. При необходимости отправляет «📷 Фото до».
4. Нажимает «📸 Фото после», прикрепляет фотографию и пишет комментарий.
5. Руководитель получает фотоотчёт и выбирает «✅ Принять» или «🔁 На
   переделку».
6. Для переделки руководитель вводит обязательный комментарий.
7. Сотрудник получает решение и может повторить отправку отчёта через карточку.

## 3. Матрица доступа

| Действие | Администратор | Управляющий | Руководитель | Сотрудник |
|---|---:|---:|---:|---:|
| Пригласить любого пользователя | Да | Нет | Нет | Нет |
| Пригласить руководителя/сотрудника | Да | Да | Нет | Нет |
| Управлять объектами и видами работ | Да | Да | Нет | Нет |
| Создать задание | Да | Да | Да | Нет |
| Видеть все задания организации | Да | Да | Нет | Нет |
| Видеть задания своей команды | Да | Да | Да | Нет |
| Исполнять свои задания | Да | Да | Да | Да |
| Проверять задания своей команды | Да | Да | Да | Нет |
| Управлять ролями и безопасностью | Да | Нет | Нет | Нет |

Каждая проверка дополнительно ограничена `organization_id`.

## 4. Техническая проверка

```bash
curl -fsS https://max.conspiracy-team.ru/healthz
curl -fsS https://max.conspiracy-team.ru/api/version
docker compose ps
docker compose logs --tail=100 bot tarantool seaweedfs caddy
```

Webhook регистрируется автоматически как
`https://max.conspiracy-team.ru/webhook`. На status page версия отображается в
блоке `DEPLOYED VERSION`.
