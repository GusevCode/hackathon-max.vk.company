# Интеграция LLM в «ЖКХ Контроль»

LLM в этом проекте должна быть помощником руководителя, а не источником
решения. Единственное юридически и бизнес-значимое решение по фотоотчёту
остаётся за руководителем или администратором.

## Что отдаём модели

После отправки фото «после» backend сохраняет бинарный файл в SeaweedFS, а в
Tarantool — метаданные задания, требования вида работы и ссылку на объект. В
очередь `inspection_requested` можно передать:

- временные подписанные URL фотографий;
- название и описание задания;
- вид работы и проверяемые признаки;
- комментарий исполнителя;
- при наличии — фотографию «до» для сравнения.

Персональные данные в prompt не передаются без необходимости. Подписанные URL
должны иметь короткий срок жизни и не должны попадать в обычные логи.

## Полезный MVP

На первом этапе модель может вернуть рекомендацию:

1. фотография относится к заданию или нет;
2. изображение достаточно резкое и освещённое для проверки;
3. какие признаки работы видны и какие не подтверждены;
4. краткое резюме комментария исполнителя;
5. confidence и список вопросов, которые должен проверить руководитель.

Пример строго структурированного ответа:

```json
{
  "relevant": true,
  "quality": "usable",
  "observations": ["пол лифта выглядит очищенным", "видны стены и кнопочная панель"],
  "missing_requirements": [],
  "recommendation": "approve",
  "confidence": 0.82
}
```

`recommendation` — только подсказка (`approve`, `rework`, `unknown`). Backend не
меняет статус задания автоматически: кнопка «Принять» или «На переделку» всегда
порождает действие пользователя с ролью руководителя и запись в аудите.

## Архитектурный порт

LLM подключается через порт application-слоя, чтобы провайдер можно было менять
без изменений сценариев MAX:

```go
type EvidenceAnalyzer interface {
    Analyze(ctx context.Context, input EvidenceInput) (EvidenceAnalysis, error)
}
```

Infrastructure-адаптер отвечает за конкретный OpenAI-совместимый, облачный или
локальный vision-модельный API. Use case отвечает за timeout, повторную попытку,
сохранение результата и отображение рекомендации руководителю. По умолчанию
функция выключена (`LLM_ENABLED=false`), поэтому отсутствие ключа провайдера не
ломает основной workflow.

## Защита и эксплуатация

- ограничить размер, тип и число изображений до отправки модели;
- задать timeout, retry с backoff, circuit breaker и лимит стоимости;
- не логировать токены, подписанные URL и полные prompt/ответы;
- сохранять версию модели, время запроса, хэш входных файлов и результат аудита;
- разрешить ручной повтор анализа и помечать ответ как устаревший после новой
  отправки фото;
- добавить политику хранения результатов на тот же срок, что и метаданных
  задания, либо короче по требованиям организации;
- тестировать adapter контрактными тестами на fixture-изображениях без реальных
  пользовательских данных.

## Этапы внедрения

1. Добавить доменный контракт `EvidenceAnalyzer` и флаг `LLM_ENABLED`.
2. Реализовать mock-анализатор и показать результат в карточке проверки.
3. Добавить очередь/worker, чтобы MAX webhook не ждал ответа модели.
4. Подключить выбранного vision-провайдера через секрет VPS/GitHub Environment.
5. Собрать датасет ошибок и ввести метрики: доля полезных рекомендаций,
   ручные исправления, среднее время проверки и стоимость на отчёт.

До появления реальных fixture-данных и решения о провайдере не следует включать
автоматическое принятие работ или отправку на переделку.

## Текущая реализация Polza.ai

В backend добавлен адаптер Polza.ai с OpenAI-совместимым API. Анализ запускается
асинхронно через NATS после отправки фотографий «после» и сохраняется в Tarantool.
Результат является подсказкой для руководителя: статус задания автоматически не
изменяется.

Для включения задайте `LLM_ENABLED=true` и секрет `POLZA_AI_API_KEY` в `.env`.
Все человекочитаемые поля ответа модели (наблюдения, комментарии, вопросы и
недостающие требования) в системном и пользовательском prompt явно требуются на
русском языке с кириллицей. Машинные enum-значения (`approve`, `rework`, `unknown`
и значения качества) остаются на английском для стабильного разбора JSON.
